# libpng G3：RVV 行过滤功能验收（2026-11-14）

上游（1.8.0.git）`riscv/` 目录只有实现文件，**没有接线**：arm/intel/mips/powerpc 都有
`check.h`，riscv 缺一个；`filter_rvv_intrinsics.c` 也未被加入任何构建列表。
所以 libpng 是本轮第一个真需要"动手接"而不是"打开开关"的包。

## 接线（补在构建副本里，`baseline/` 保持原样）

1. 新增 `riscv/check.h`，仿 `arm/check.h`：定义 `png_target_impl`、
   `PNG_TARGET_IMPLEMENTS_FILTERS`、`PNG_TARGET_CODE_IMPLEMENTATION "riscv/riscv_init.c"`，
   并把 `png_target_init_filter_functions_impl` 映射到 `png_init_filter_functions_rvv`。
2. `pngtarget.h` 的架构 include 列表加 `riscv/check.h`。
3. `pngpriv.h` 补 7 个 row filter 的原型（`up` / `sub3` / `sub4` / `avg3` / `avg4` /
   `paeth3` / `paeth4`），否则 `riscv_init.c` 里就是隐式声明。
4. `riscv_init.c` 去掉 `#include "../pngpriv.h"`——它由 `pngsimd.c` 包含，
   重复包含会直接 `#error Duplicate inclusion of pngpriv.h`。
5. `filter_rvv_intrinsics.c` 作为**独立 TU** 加入 `libpng_sources`（它自己 include
   `pngpriv.h`，不能塞进 `riscv_init.c`）。

| 侧 | 配置 |
|---|---|
| A | 上述接线 + `-DPNG_RISCV_RVV_IMPLEMENTATION=1`，`-march=rv64gcv` |
| B | 上游原样（无接线，纯 C），同一 `-march=rv64gcv` |

riscv64 侧没有预编译 zlib，A/B 两侧共用 zlib-ng G3 产出的 `off` 前缀（标量静态库），
所以唯一变量仍是 libpng 的 RVV。

## 结果

| 项 | A | B |
|---|---|---|
| PNG 码流 | `png=28995 fnv_png=3bd158cdb34ca865` | 同左 |
| 解码像素 | `fnv_px=7322844870c2c46b` | 同左 |

## 变异测试（证明路径真的在跑）

"打开宏但实际走 C 路径"是这类包最容易出现的假通过。做法是故意在
`png_read_filter_row_up_rvv` 的 `vse8` 之后翻一个字节，重编 A 侧：

- 正常 A 侧：harness PASS，哈希如上；
- 变异 A 侧：harness 直接报 `pixel mismatch`（exit 11）。

说明 UP 过滤确实由 RVV 内核执行，A/B 对比有效。这个检查已固化成
`scripts/mutation-check.sh`。

真机性能：`build/rvv-k/{on,off}/bench`（`bench_png <file.png>`，1024x768 解码）。
